This file is a human-readable snapshot. The gate reads
frontend/typecheck-baseline.json; nothing reads this one.

The baseline held 30 pre-existing errors for most of the stabilization
programme. All 30 were audited and resolved. Roughly half were not the harmless
type-noise they appeared to be:

  RUNTIME CRASH (1 defect, 3 errors)
    DashboardPage rendered `metrics.summaryTitle` inside a banner whose own
    show-condition is TRUE when `metrics` is null. The only early return on the
    page is for `loading`, so a failed metrics fetch left metrics null, loading
    false, and the banner rendering — throwing into the route error boundary and
    white-screening Store Overview. The page already had an honest "could not
    load" banner; it never got the chance to show it.

  SILENT NO-OP PROP VALUES (3 defects, 9 errors)
    Polaris rejects unknown token values by falling back to a default, so these
    looked deliberate and did nothing:
      gap="250"              — space-250 does not exist; those layouts had NO gap
      Banner tone="attention" — Banner allows only success|info|warning|critical
      Badge tone="subdued"    — not in the Badge tone union
    Root cause of the Banner case: one tone function fed both Badge and Banner,
    which have different unions.

  LOST TYPE SAFETY ON LOAD-BEARING PATHS (6 errors)
    backendModuleAccess.js and starterModuleMutation.js had no .d.ts, so every
    import was `any` — on the ENTITLEMENT path and the billing-approval rule.
    `isBackendModuleEnabled(appState, "pricng")` compiled fine. Declaration
    files added; adding them immediately surfaced two further errors that the
    `any` had been hiding.

  TYPE CONTRACT COLLAPSED TO `never` (6 errors)
    `SyncActivitySummary["moduleProcessing"][keyof ...]` resolves to `never`,
    because `moduleProcessing` is optional and `keyof (T | undefined)` is
    `never`. deriveQuickAccessDisplay therefore had NO checking on the path that
    decides what each Quick Access card tells the merchant.

  GENUINELY HARMLESS, FIXED FOR ACCURACY (5 errors)
    Nullable render values, an unguarded `.map` already gated by a `?? []`
    length check, a number passed as Badge children, and an incomplete
    AppState.onboarding declaration where the backend spreads the full object.

No error was suppressed, and no unrelated refactor was made to reach zero.
